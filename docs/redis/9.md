## 1. Overview

* **`DEL`** removes a key and its allocated memory across **any** Redis data type (Strings, Hashes, Lists, Sets, etc.).
* **`GETRANGE`** and **`SETRANGE`** provide byte-level and character-level slicing and in-place mutation directly inside system RAM without transferring the entire string across the network.
* These commands optimize bandwidth and processing power when working with large serialized payloads, fixed-width protocols, or binary buffers.

---

## 2. Key Concepts

### Command Signatures

```redis
# Key Deletion (Universal)
DEL key [key ...]

# Substring Retrieval (Read)
GETRANGE key start end

# In-Place Overwrite (Write)
SETRANGE key offset value

```

* **`DEL`**: Removes one or more keys from the keyspace. Returns the integer count of keys actually removed.
* **`GETRANGE`**: Returns the substring between the `start` and `end` offsets (both inclusive). Formerly known as `SUBSTR`.
* **`SETRANGE`**: Overwrites part of an existing string stored at `key`, starting at the specified byte `offset`, for the length of `value`. Returns the new total string length.

---

## 3. How It Works

### 1. Zero-Based & Negative Indexing (`GETRANGE`)

Redis treats strings as contiguous byte arrays. Offsets are **zero-based** and fully support Python-style negative indices:

* `0` is the first byte/character.
* `-1` is the last byte/character.
* `-2` is the penultimate (second to last) character.
* Ranges that exceed string boundaries are automatically clamped to the actual length without throwing errors.

```
 String:     T   o   y   o   t   a
 Positive:   0   1   2   3   4   5
 Negative:  -6  -5  -4  -3  -2  -1

```

### 2. In-Place Overwrite & Zero-Padding (`SETRANGE`)

* When modifying an existing string, Redis overwrites bytes starting at `offset`. If `offset + value_length` exceeds the current string length, the string grows dynamically.
* **Zero-Padding Allocation:** If `SETRANGE` is executed on a non-existent key, or at an offset beyond the current string length, Redis fills the gap with **zero bytes (`\x00`)** before appending the new characters.

```
Original:       [ T ] [ o ] [ y ] [ o ] [ t ] [ a ]
SETRANGE 2 "lu"  -->  Overwrites index 2 and 3
Result:         [ T ] [ o ] [ l ] [ u ] [ t ] [ a ]  (Length: 6)

```

### 3. Key Deletion (`DEL` vs. Event Loop Execution)

* `DEL` operates synchronously. When invoked, Redis removes the key from its internal dictionary and immediately reclaims the memory.
* For small string keys, deletion is virtually instantaneous ($O(1)$).

## 4. Practical Examples

### 1. Deleting Keys (`DEL`)

```redis
# Populate and delete
SET color "red"
GET color
# Output: "red"

DEL color
# Output: (integer) 1  <-- 1 key deleted

# Verify deletion
GET color
# Output: (nil)

# Multi-key deletion
SET key1 "a"
SET key2 "b"
DEL key1 key2 non_existent_key
# Output: (integer) 2  <-- Only counts keys that actually existed

```

### 2. Extracting Substrings (`GETRANGE`)

```redis
SET model "Toyota"

# 1. Standard slice: Index 0 to 2 (inclusive)
GETRANGE model 0 2
# Output: "Toy"

# 2. Extract the last 3 characters using negative indexing
GETRANGE model -3 -1
# Output: "ota"

# 3. Read entire string from index 2 to end
GETRANGE model 2 -1
# Output: "yota"

# 4. Out-of-bounds range (automatically clamped)
GETRANGE model 0 100
# Output: "Toyota"

```

### 3. In-Place Mutation & Expansion (`SETRANGE`)

```redis
SET model "Toyota"

# Overwrite starting at index 2 with "lou" (replaces 'y', 'o', 't')
SETRANGE model 2 "lou"
# Output: (integer) 6  <-- Returns new string length

GET model
# Output: "Toloua"

# Zero-padding demonstration on an offset gap
SETRANGE greeting 5 "Hello"
# Output: (integer) 10

# Bytes 0 to 4 are filled with null bytes (\x00)
GET greeting
# Output: "\x00\x00\x00\x00\x00Hello"

```

## 5. Important Comparisons

### `DEL` vs. `UNLINK` (Crucial Interview Distinction)

| Feature | `DEL` | `UNLINK` |
| --- | --- | --- |
| **Execution Model** | Synchronous (blocking) | Asynchronous (non-blocking) |
| **Memory Reclamation** | Reclaimed immediately in main thread | Reclaimed in a background worker thread |
| **Event Loop Impact** | Can freeze Redis on massive data structures | Zero blocking latency on the main event loop |
| **Recommended Usage** | Strings and small keys | Large collections, massive Hashes/Sets/Lists |

### `GETRANGE` vs. `SUBSTR`

* `SUBSTR` is the older command name from Redis 1.0.
* `GETRANGE` was introduced in Redis 2.0 to standardize naming conventions alongside `SETRANGE`.
* `SUBSTR` is kept as a backwards-compatible alias; **always use `GETRANGE**` in modern code.

---

## 6. When to Use

* **`DEL`**: Immediate purging of cache records upon database writes, or invalidating session tokens upon user logout.
* **`GETRANGE`**:
* Inspecting message headers inside binary payloads without downloading the full payload over the network.
* Paginating through large fixed-width text records.


* **`SETRANGE`**:
* Patching specific bytes or flags in large serialized payloads without re-uploading entire objects.
* Updating bitmask-like structures or custom binary data files directly in RAM.



---

## 7. Advantages and Limitations

### Advantages

* **Network Bandwidth Savings**: Slicing or patching strings on the server prevents transferring multi-megabyte payloads back and forth to application servers.
* **Zero-Copy Bounds Safety**: `GETRANGE` does not fail or crash on out-of-bound indices; it returns the best-fit substring or an empty string.

### Limitations

* **UTF-8 Multi-Byte Hazards**: Both `GETRANGE` and `SETRANGE` operate on **raw byte offsets**, not unicode characters. Cutting a multi-byte UTF-8 character (e.g., emojis or non-Latin alphabets) in half causes data corruption.
* **Memory Allocation Spike via `SETRANGE**`: Specifying an excessively high offset on an empty key forces Redis to allocate all intermediate memory as `\x00` bytes immediately, which can cause out-of-memory errors.

## 8. Additional Knowledge (System Internals & Gotchas)

### The `DEL` Blocking Trap

While `DEL` on a simple String is an $O(1)$ constant-time operation, calling `DEL` on an aggregate key (such as a Hash or Set with millions of elements) is **$O(N)$**.

* Because Redis is single-threaded, freeing millions of memory pointers synchronously will freeze the server for hundreds of milliseconds.
* **Production Standard:** Use `UNLINK` instead of `DEL` for unknown or large keys to move deallocation off the main event loop.

### Complexity Matrix

| Command | Time Complexity | Notes |
| --- | --- | --- |
| **`DEL`** | $O(N)$ | $N$ is the number of keys. For strings, it is $O(1)$. For aggregate collections, $N$ is the number of nested elements. |
| **`GETRANGE`** | $O(S)$ | $S$ is the length of the extracted string. Fast because it only copies the requested slice. |
| **`SETRANGE`** | $O(1)$ amortized | Copying length is typically small; memory reallocation happens if length extends. |

## 9. Interview Preparation

### Q1: What happens if you execute `SETRANGE mykey 1000 "data"` when `mykey` does not exist?

**Answer:** Redis creates a new key. Because the offset is 1000, Redis fills byte offsets 0 through 999 with zero bytes (`\x00`), appends `"data"` at offset 1000, and returns a total length of `1004`.

### Q2: Why is using `DEL` considered dangerous in high-load production systems?

**Answer:** `DEL` is a synchronous, blocking command. If executed against a key containing a large collection (e.g., a Sorted Set with 2 million entries), the main thread freezes while freeing the memory, causing request timeouts across all other connected clients. `UNLINK` should be used instead for asynchronous, non-blocking deallocation.

### Q3: How does `GETRANGE` handle negative indexes?

**Answer:** Negative indices count backward from the end of the string, where `-1` represents the last character, `-2` the second to last, and so on. For example, `GETRANGE key -4 -1` extracts the last 4 characters of the value.

---

## 10. Quick Revision

* `DEL key [keys...]` deletes keys across any data type ($O(1)$ for strings, $O(N)$ for aggregate types).
* Use `UNLINK` instead of `DEL` to delete large keys without blocking the single-threaded event loop.
* `GETRANGE key start end` retrieves a substring inclusively using zero-based and negative indexing.
* `GETRANGE` replaces the deprecated `SUBSTR` command.
* `SETRANGE key offset value` updates a string in-place starting at byte `offset`.
* If `SETRANGE` targets an offset past the end of a key, the gap is padded with null bytes (`\x00`).
* Both `GETRANGE` and `SETRANGE` operate on **raw bytes**, making multi-byte UTF-8 character splitting a potential risk.
