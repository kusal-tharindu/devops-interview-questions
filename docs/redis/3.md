## 1. Redis Command & Execution Model

Redis operates on a client-server protocol (RESP — REdis Serialization Protocol):
- Clients send commands as arrays of strings.
- The Redis engine executes the command against the in-memory keyspace and returns typed responses (e.g., Simple String `OK`, Bulk String, Integer, Array, or Nil).

    [ Client Application ] ──── "SET message 'Hi there'" ────► [ Redis Server ]
                           ◄───────── "+OK" ───────────────

- **Key**: Unique, binary-safe identifier in the keyspace.
- **Value**: The data stored at that address, backed by a specific Redis data structure.

## 2. Redis Data Structures Overview

Commands are strictly partitioned by data type[cite: 2]. The diagram below outlines the core and extended data types supported by modern Redis:

| Data Type | Description | Primary Commands | Common Use Cases |
| :--- | :--- | :--- | :--- |
| **String** | Stores a plain string or numeric value[cite: 2]. | `SET`, `GET`, `APPEND`[cite: 2] | Caching, session tokens, atomic counters, distributed locks. |
| **List** | Ordered collection of strings (linked list)[cite: 2]. | `LINDEX`, `LLEN`, `LINSERT`[cite: 2] | Message queues, event logs, recent timeline feeds. |
| **Hash** | Collection of field-value pairs[cite: 2]. | `HGET`, `HSET`, `HDEL`[cite: 2] | Representing objects/records (e.g., user profiles). |
| **Set** | Unordered collection of unique strings[cite: 2]. | `SADD`, `SCARD`, `SDIFF`[cite: 2] | Unique visitor tracking, tag filters, social graphs (mutual friends). |
| **Sorted Set (ZSet)**| Set of unique strings ordered by a floating-point score[cite: 2]. | `ZADD`, `ZDIFF`, `ZCOUNT`[cite: 2] | Leaderboards, rate limiters (sliding window), priority queues. |
| **Bitmap** | String manipulated at the bit level; functions like a collection of booleans[cite: 2]. | `BITOP`, `BITCOUNT`, `BITPOS`[cite: 2] | Daily active user (DAU) flags, user retention tracking. |
| **HyperLogLog** | Probabilistic data structure for estimating cardinality (unique elements) with fixed memory (~12 KB). | `PFADD`, `PFCOUNT`, `PFMERGE`[cite: 2] | Counting billions of unique website visits or search queries with ~0.81% error margin. |
| **JSON** | Hierarchical, nested JSON document support[cite: 2]. | `JSON.SET`, `JSON.GET`, `JSON.DEL`[cite: 2] | Storing and querying nested domain objects without manual serialization. |
| **Index (Search)** | Secondary indices used for text search, numeric filtering, and vector similarity[cite: 2]. | `FT.SEARCH`, `FT.CREATE`, `FT.PROFILE`[cite: 2] | Full-text search, auto-complete, vector search for AI embeddings. |

> [!NOTE] HyperLogLog vs. Bitmap
> While course diagrams sometimes categorize HyperLogLog alongside bit manipulation[cite: 2], HyperLogLog is strictly a **probabilistic cardinality counter**. Use **Bitmaps** when you need exact boolean values at precise indices[cite: 2], and use **HyperLogLog** when you need to count millions/billions of unique items using minimal fixed memory[cite: 2].

## 3. Working with Strings

### `SET` & `GET`
```redis
# Write a key-value pair
SET message "Hi there"
# Output: OK

# Retrieve value
GET message
# Output: "Hi there"

# Non-existent key lookup
GET unknown_key
# Output: (nil)
```

### `APPEND`
Appends a string value to an existing key[cite: 2]. If the key does not exist, it creates it with an empty value first, behaving like `SET`.

```redis
APPEND message "!"
# Output: (integer) 9  (returns the new length of the string)

GET message
# Output: "Hi there!"
```

## 4. Strict Type Enforcement (`WRONGTYPE`)

Every Redis key points to an internal header (`redisObject`) defining its underlying type. Executing a command on an incompatible data structure immediately halts:

```redis
# Example: Adding to a Set, then invoking a String command
SADD user:tags "developer"
GET user:tags
```
**Output:**
```
(error) WRONGTYPE Operation against a key holding the wrong kind of value
```

## 5. Redis Strings: Under the Hood

- **Binary-Safe**: Strings can hold arbitrary data up to **512 MB** (text, raw binary, serialized JSON/Protobuf, or media blobs).
- **Simple Dynamic String (SDS)**:
  - Redis wraps native C strings in an internal `sdshdr` struct.
  - Length is stored in memory alongside data, making `STRLEN` an **O(1)** operation.
  - Prevents buffer overflow exploits common in plain C arrays.
- **Internal Encodings (`OBJECT ENCODING <key>`)**:
  - `int`: 64-bit signed integers (allows atomic increments via `INCR`).
  - `embstr`: Strings under 44 bytes allocated contiguously with object headers for CPU cache efficiency.
  - `raw`: Dynamic memory allocation for strings greater than 44 bytes.

## 6. Production `SET` Modifiers & Flags

In high-throughput architectures, raw `SET` operations are paired with atomic control flags:

```redis
SET key value [NX | XX] [GET] [EX seconds | PX milliseconds | EXAT timestamp | PXAT timestamp-milliseconds]
```

| Modifier | Function | Production Pattern |
| :--- | :--- | :--- |
| `NX` | Set only if the key does **not** already exist. | Distributed mutex locks. |
| `XX` | Set only if the key **already** exists. | Updating cache values without introducing orphan keys. |
| `EX / PX` | Attaches a time-to-live (seconds / milliseconds). | Cache TTL, ephemeral sessions. |
| `GET` | Sets the new value and returns the old value atomically. | Atomic config swaps without race conditions. |

```redis
# Production Distributed Lock Pattern (O(1))
SET lock:order_payment "worker_node_01" NX EX 15
```

## 7. Complexity Reference

| Command | Complexity | Operational Detail |
| :--- | :--- | :--- |
| `SET` | O(1) | Constant time write and allocation. |
| `GET` | O(1) | Constant time memory lookup. |
| `APPEND` | O(1) | Amortized constant time string buffer extension[cite: 2]. |
| `STRLEN` | O(1) | Constant time header read via SDS metadata. |
| `DEL` | O(1) | Instant pointer deallocation (for standard strings). |
