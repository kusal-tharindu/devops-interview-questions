## 1. How to Read Redis Command Documentation

The official documentation (`redis.io/commands`) uses a standardized syntax notation[cite: 7]:

    SET key value [EX seconds | PX milliseconds | EXAT unix-time-seconds | PXAT unix-time-milliseconds | KEEPTTL] [NX | XX] [GET]

### Syntax Conventions
- **Capitalized Words**: Literal keywords that must be typed exactly as shown (e.g., `SET`, `GET`, `NX`, `EX`)[cite: 7].
- **Lowercase Words**: User-provided arguments, keys, or values (e.g., `key`, `value`, `seconds`)[cite: 7].
- **Square Brackets `[...]`**: Optional arguments that can be omitted[cite: 7].
- **Vertical Pipe `|`**: Mutually exclusive options ("OR")[cite: 7]. You may select at most one option from the group[cite: 7].

## 2. String Command Taxonomy: Getters vs. Setters

String operations are divided broadly into commands that retrieve data (Getters) and commands that write or modify data (Setters)[cite: 4]. Rather than memorizing every command, they group into core operations, atomic variations, and specialized tools[cite: 5].

```
                     ┌─────────────────────────────────────────┐
                     │          String Command Groups          │
                     └────────────────────┬────────────────────┘
                                          │
                  ┌───────────────────────┴───────────────────────┐
                  ▼                                               ▼
         ┌──────────────────┐                            ┌──────────────────┐
         │ Getters (Read)   │                            │ Setters (Write)  │
         ├──────────────────┤                            ├──────────────────┤
         │ Core: GET        │                            │ Core: SET        │
         │ Multi: MGET      │                            │ Multi: MSET      │
         │ Atomic: GETDEL,  │                            │ Atomic: SETNX,   │
         │         GETEX    │                            │         SETEX    │
         │ Niche: GETRANGE, │                            │ Niche: SETRANGE, │
         │        LCS       │                            │        APPEND    │
         └──────────────────┘                            └──────────────────┘
```

## 3. Command Breakdown & Functional Grouping

### Core Retrieval (Getters)

| Command | Category | Functionality | Production / Interview Note |
| :--- | :--- | :--- | :--- |
| **`GET`**[cite: 3, 4] | Core | Retrieves the value of a string key[cite: 4]. | Returns `(nil)` if the key does not exist. |
| **`MGET`**[cite: 3, 4] | Multi-Key | Retrieves values for multiple keys in a single roundtrip[cite: 4, 5]. | Crucial for eliminating network roundtrip latency (RTT). |
| **`GETDEL`**[cite: 3, 4] | Atomic Variant[cite: 5] | Returns the value and atomically deletes the key[cite: 4]. | Ideal for single-use tokens, OTP verification, or atomic queue processing. |
| **`GETEX`**[cite: 3, 4] | Atomic Variant[cite: 5] | Returns the value while atomically setting or modifying its TTL. | Used for sliding session expirations on read without extra roundtrips. |
| **`GETRANGE`**[cite: 3, 4] | Niche / Offset[cite: 5] | Retrieves a substring by start and end byte offsets[cite: 5]. | Replaces the deprecated `SUBSTR` command[cite: 3, 4]. |
| **`LCS`**[cite: 3, 4] | Specialized[cite: 5] | Computes the Longest Common Subsequence between two string keys[cite: 5]. | In-memory diffing, text comparison, and sequence analysis without data transfer. |

### Core Mutation (Setters)

| Command | Category | Functionality | Modern Standard / Status |
| :--- | :--- | :--- | :--- |
| **`SET`**[cite: 3, 4] | Core | Stores a string value at a key[cite: 4]. | Supports options (`NX`, `XX`, `EX`, `PX`, `GET`)[cite: 6, 7]. |
| **`MSET`**[cite: 3, 4] | Multi-Key[cite: 5] | Sets multiple key-value pairs atomically[cite: 4]. | All-or-nothing execution across provided keys. |
| **`MSETNX`**[cite: 3, 4] | Multi-Key[cite: 5] | Sets multiple keys only if **none** of them already exist[cite: 4]. | Fails completely if even one key is already present. |
| **`SETNX`**[cite: 3, 4] | Legacy Variant[cite: 5] | "Set if Not eXists"[cite: 5]. | **Superseded** by `SET key val NX`. |
| **`SETEX`**[cite: 3, 4] | Legacy Variant[cite: 5] | Sets key with a TTL in seconds[cite: 5]. | **Superseded** by `SET key val EX <sec>`. |
| **`GETSET`**[cite: 3, 4] | Deprecated | Sets new value and returns previous value[cite: 4]. | **Deprecated** in Redis 6.2; use `SET key val GET`. |
| **`APPEND`**[cite: 3, 4] | Specialized[cite: 5] | Appends a string to the existing value[cite: 4]. | Returns the new total string length; amortized $O(1)$[cite: 2]. |
| **`SETRANGE`**[cite: 3, 4] | Specialized[cite: 5] | Overwrites part of a string starting at a specified byte offset[cite: 4, 5]. | Used for in-place buffer updates and binary protocol masks. |
| **`STRLEN`**[cite: 3, 4] | Metadata | Returns string length in bytes[cite: 4]. | $O(1)$ constant time lookup due to internal SDS structure. |
| **`DEL`**[cite: 3, 4] | Deletion | Removes the key and its memory allocation[cite: 4]. | Shared command across all Redis data structures[cite: 3]. |

## 4. Modern Redis Best Practices (Interview Essentials)

### 1. Avoid Deprecated Commands
Many commands persist strictly for backwards compatibility:
- Use `SET key val NX` instead of `SETNX key val`.
- Use `SET key val EX <seconds>` instead of `SETEX key <seconds> val`.
- Use `SET key val GET` instead of `GETSET key val`.
- Use `GETRANGE` instead of `SUBSTR`[cite: 3, 4].

### 2. Multi-Key Operations in Redis Cluster (`CROSSSLOT` Hazard)
While `MGET` and `MSET` minimize network latency in standalone Redis[cite: 3, 4], they present architectural risks in **Redis Cluster**:
- A multi-key command requires all target keys to live on the **exact same hash slot** (node).
- If keys hash to different slots, the cluster returns an error:
  `CROSSSLOT Keys in request don't hash to the same slot`
- **Solution (Hash Tags)**: Force related keys onto the same slot by wrapping the common partition key in curly braces:
  `MGET {user:101}:name {user:101}:email`

### 3. Substring & Offset Operations Complexity
- `GET` and `SET` operate in $O(1)$ time.
- `GETRANGE` and `SETRANGE` depend on the range size: $O(S)$ where $S$ is the length of the substring[cite: 3, 4]. Avoid large ranges on multi-megabyte strings to prevent blocking Redis's single-threaded event loop.
